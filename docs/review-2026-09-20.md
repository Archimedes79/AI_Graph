# Code review — locality, quality, consistency, homogeneity

Reviewed on 2026-09-20 at `3413460` (`main`), and worked through on 2026-09-21 on
`refactor/consistency-layering`. Everything below was measured on the source, not remembered; the
scripts were throwaway and are not part of the repository, so each number is given with the question
it answers. [architecture.md](architecture.md) says how the code is meant to be; this file says where
it was not, what was done about it, and what is left.

## Verdict

The structure held. The rules a test could enforce were enforced. What was left sat where no test
looked: the engine's half of "shells never name a kind", one prompt that listed every kind by hand,
an editor with layers nobody had written down, and a few leftovers of formats that lived for days.
Those are now either fixed and held by a test, or named below as not done.

## What was done

**Locality — an element owns everything about its kind**

- `check.ts` no longer knows what a code node, an ai node or a page is. The three checks moved into
  `CodeNodeRunner.problems`, `AiNodeRunner.problems` and `GuiNodeRunner.problems`; the read of
  `read_file_inputs` became `readsFileInputs(node)`; "does the graph end in something a person sees" asks
  the new `NodeRunner.isResult` instead of naming `output`.
- `executor.finalOutputs` asks `isResult` the same way.
- `project/folder.ts` no longer reads `config.gui_widgets` (it did so four times, with a cast each): it asks
  `NodeRunner.blocks(node)` and puts sorted blocks back with `setBlocks`, the same pair `nestedGraph` and
  `setNestedGraph` already were. It "never learns what a code node is" now holds for a page as well.
- `graphPrompt.ts` had a hand-written list of node types, and it **had no `subgraph`**. The kinds are now
  listed from the registry, and each says how its settings are written in its own `graphAuthorNote()`. A kind
  without one is not offered to the model; a test pins that to exactly `subgraph`, so a new kind that forgets
  its note fails instead of silently missing.
- The rule now has an engine test: [`engine/src/shells.test.ts`](../engine/src/shells.test.ts).

**Consistency**

- `errors.ts` holds `NotFound` and `NotAGraph` once. `routes.ts:230` no longer has to ask for both copies.
- `mcpServer.ts` told a document that is not a graph from a path that may not be opened by matching a regex
  on the *message*. The class that was meant to say it (`NotAGraph extends Refused`) existed and nothing
  used it. It is `BadDocument` now, and `validate_graph` asks `instanceof`.
- `message(error)` was defined twice; `valuePorts` twice and `WRITE_PATH_PORT` twice (one in `boundary.ts`,
  which says in its own header that it "holds no second copy of anyone's settings"). It is now
  `NodeRunner.valuePorts`, answered by `OutputNodeRunner`, and the boundary asks the element.
- Two different functions both named `displayValue` (one pretty-prints for editing, one is a one-line
  summary) are `asEditableText` and `oneLine`.
- `GuiPage.tsx` exported a component nobody imported and had two doc comments stacked on one function;
  `CodeNodeRunner` had a comment left over from a member that moved.

**Layering — the editor's layers are written down and held**

`ui` · `graph` · `document`, `api` · `store` · `dialogs` · `elements`, `authoring` · `page`, `canvas` · `app` ·
`App`, `runtime` · `main`. Twelve modules moved to where that order says they belong:

| Module | From | To | Why it was in the wrong place |
|---|---|---|---|
| `scheme.ts`, `tone.ts` | `page/` | `ui/` | look; `elements/` and `authoring/` needed them |
| `layout.ts` | `page/` | `document/` | the grid a page's blocks sit on; `elements/` needed a constant |
| `executionStatus.ts`, `nodeData.ts` | `canvas/` | `store/` | the store imported them from the canvas above it |
| `WhatRuns.tsx` | `canvas/` | `elements/fields/` | used by the canvas *and* the designer |
| `FileBrowserDialog`, `RequirementsDialog` | `ui/` | `dialogs/` | they call the server and read the store: not look |
| `nodeKinds.ts`, `baseNodeConfig.ts`, `guiWidgets.ts` | `src/`, `elements/nodes/` | `document/` | the store loads and saves nodes; it must not reach into `elements/` |

`elements` ↔ `authoring` remains one tier and reaches itself on purpose (a panel is made of authoring
editors; an authoring editor asks the registry what a node is; panels are lazy). `layers.test.ts` names it.

**Dead code and things built for a past that no longer exists**

- `project/legacy.ts` (reading `<graph>.nodes/` with a `code_file` pointer) and `triggersAsNodes` in
  `graph.ts` (turning two old settings into a trigger node) were compatibility with formats that lived for
  days and that nothing writes. With them went three tests and two sentences of documentation. A graph
  saved in the old way no longer opens with its code; the code is in `<graph>.nodes/` and can be pasted back.
- 21 functions and constants that were `export`ed and imported by nobody are not exported.

## Not done, and why

- **The long shells.** 27 of 908 functions are over 100 lines; `App` (588), `Toolbar` (570),
  `createGraphTools` (366 lines, 102 branches), `NodeEditor` (358), `executeGraph` (259, 71 branches),
  `editorRoutes` (207). They are layout and wiring, the risk of a split is highest there, and nothing in
  this pass would have caught a mistake in one. `graphStore.ts` (910 lines) still holds the document, its
  normalisation, the ReactFlow adapter, run polling and undo. These are the next things to cut, in that order.
- **`AI_RUN_TEMPLATES`** is a list of one, and `earlier` in `ElementRunner.texts` is that list. Built from
  scratch it would be one constant; kept, because the next change to `run.js` is exactly when it pays.
- **`clamp`** exists in the slider runner (engine) and in `document/layout.ts` (editor). Three lines on two
  sides of a wire that share no module; a shared one would cost more than the copy.
- **The engine has no typed `NodeConfig`.** The 652 casts are the price, and each element's `config()` is the
  only reader that should pay it. `mcpServer.ts` still validates `config.gui_widgets` entries by name, on a
  document that has not been parsed yet.
- **`elements/authoring`** is one tier, not two. Splitting `authoring/` into the editors a panel is made of and
  the page-wide sweep that asks the registry would remove the sideways pair; it is a larger move than the
  rest and is not needed for the deployment boundary, which `runtime/boundary.test.ts` holds.
- **Editor tests** are 16 % of source lines and nearly all of them guard the structure; `App`, `Toolbar`,
  the canvas and the designer have no unit test.
- **Comments that narrate history** ("it used to be…") appear a few dozen times. They explain why the code is
  the way it is and are kept; a future pass could keep the reason and drop the story.
